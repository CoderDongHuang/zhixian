# AI 问答与研究代理 Runbook

更新日期：2026-08-26

研究代理位于 `/research/agent`，只接受当前登录用户拥有的研究专题。V0.1 使用可持久化状态机代替独立队列：创建任务时收集并冻结证据和大纲，状态进入 `AWAITING_CONFIRMATION`；用户确认后同步生成并持久化报告。页面离开不会丢失等待确认的任务。

## 证据与回答边界

- 只从专题条目关联的已发布事件、实体提及事件和简报事件中取证，不执行开放网络搜索。
- 单任务最多读取 30 个专题条目、120 个候选事件，按研究对象均衡冻结最多 40 条证据；证据文本最多 700 字。
- 每个用户每小时最多创建 20 个任务，超限接口返回 429；该限制同时约束模型成本和任务表增长。
- `CHANGES_30D` 只保留生成任务时过去 30 天内发生或发布的证据。
- `COMPARE` 由用户从专题中明确选择两个不同对象，且两者必须各自有证据；无证据或对象不足时明确拒答。
- 回答每个事实必须引用冻结快照中的 evidence id。模型 JSON 损坏、结构不合规、无引用或越界引用时废弃模型结果并改用规则报告。
- 规则模式不补充专题外知识。模型可输出 `INFERENCE`，界面会明确标为“推测”，但仍必须引用其推理依据。

## 模型配置

默认不需要模型配置，系统使用 `rules-v1` 确定性报告，适合本地、测试和故障降级。启用兼容 Chat Completions 的模型时配置：

```text
RESEARCH_AI_API_KEY
RESEARCH_AI_API_URL
RESEARCH_AI_MODEL
RESEARCH_AI_TIMEOUT_MS
```

生产 URL 必须使用 HTTPS；本地仅允许 `localhost` 或 `127.0.0.1` 使用 HTTP。超时限制在 5-60 秒。请求只包含用户问题、专题对象和受长度限制的冻结证据，不包含 API key、登录凭据、个人笔记或整篇原文。供应商错误原文不会写入任务或展示给用户。

## 状态与恢复

所有状态转换写入 `ResearchAgentEvent`，且任务、列表、确认、取消和重试接口都按 `userId` 隔离。

1. `AWAITING_CONFIRMATION`：可确认或取消。
2. `RUNNING`：已领取执行权；条件更新阻止重复确认。
3. `COMPLETED`：回答和生成方式已持久化。
4. `REFUSED`：证据为空或比较条件不足。
5. `FAILED`：可使用原冻结证据重试。
6. `CANCELLED`：报告未生成。

模型最长超时 60 秒。任务在 `RUNNING` 超过 10 分钟后视为中断，所有者可在页面使用原冻结证据恢复。不要直接在数据库把任务改为完成。已进入终态的任务、证据快照和事件记录保留 365 天，由 `npm run data:cleanup` 清理。

## 上线检查

1. 按数据库迁移 Runbook 创建备份并执行 `npm run db:migrate:deploy`。
2. 不配置模型先验证规则模式：创建任务、核对大纲和来源、确认报告、点击每个引用。
3. 配置模型后用包含冲突证据的专题验证逐事实引用与推测标记。
4. 使用第二个账户验证任务列表以及确认、取消、重试接口均返回 404。
5. 验证空专题、30 天无材料、单对象比较会拒答。
6. 执行 dry run 检查 365 天终态任务清理数量；无需新增定时 GitHub Actions，当前账户预算恢复前继续人工运行。
