### 使用与边界

`npm run configuration:check` 默认只做安全静态预检，使用 Next 自身环境文件优先级（shell 优先于 `.env.local` 和 `.env`）。`npm run configuration:check -- --production` 增加生产约束，但读取的仍是当前进程/文件，不会自动读取 Vercel、GitHub 或 EAS 的配置。

显式添加 `--database` 才连接 `DATABASE_URL` 与 `DIRECT_URL`，各自验证 `BEGIN READ ONLY`、迁移完成记录与脚本 checksum、实际 `vector(1024)` 列；结束时回滚，没有 migrate、写业务记录或读取业务正文。`--no-env-files` 可禁用文件加载，适用于已经注入完整配置的隔离环境。数据库每次连接/查询限时 5 秒。

JSON 只输出固定检查名、状态和错误类别，不输出密钥、地址、模型名、请求正文或供应商错误。`CHECKS_PASSED` 只表示本次检查通过，`releaseReady` 始终为 false；缺项/冲突为 `BLOCKED`。Node CLI 退出码 0 = 当前检查通过；2 = 检查发现阻塞；1 = 工具/参数不可用。专用测试已经加入完整 CI。

迁移 checksum 兼容 Prisma 官方的换行及旧十六进制格式，避免 Windows 检出文件对 Linux 部署记录误报；依据 [Prisma 官方实现](https://github.com/prisma/prisma-engines/blob/main/schema-engine/connectors/schema-connector/src/checksum.rs)。台账一致不证明完整 schema 无漂移，也不证明 runtime/direct 指向同一生产实例、备份可恢复或 pgvector 查询质量。
