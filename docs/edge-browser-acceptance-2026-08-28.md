# Microsoft Edge 全链路验收（2026-08-28）

## 范围与环境

本轮复核 P0、P1、P2 以及 6.1 可信研究工作台、6.2 趋势监测、6.3 AI 问答与研究代理、6.4 学习功能升级。按产品决策，6.5 团队与企业版、6.6 多行业扩展不在本轮范围。

验收使用本机已安装的 Microsoft Edge 正式版，以可见窗口分别运行桌面视口和 Pixel 7 移动视口。数据写入独立的本地 `pgvector/pgvector:pg16` 数据库，不访问或修改生产业务数据，不发送真实邮件、简报或推送。由于 Windows 桌面控制内核无法初始化，本轮由 Playwright 的 `msedge` channel 驱动 Edge 本体完成真实点击、输入、对话框确认、Cache Storage 检查和文件下载。

## 本轮发现并修复

1. 偏好页再次打开时使用默认值，保存一项会覆盖其他既有设置。现已增加登录用户偏好读取接口，页面完成加载后回填全部字段。
2. 全站搜索被外部 Embedding 接口最长阻塞 15 秒，导致数据库中明确存在的实体也一直显示“正在搜索”。现已先并行执行本地实体、别名、事件标题和已发布分析文本搜索；没有文本结果时才调用语义搜索，外部请求限制为 5 秒，响应和向量查询异常均安全降级。页面补充错误态、按钮忙碌态和 `finally` 收尾。
3. Edge 推送注册无返回时按钮永久无反馈。现已增加浏览器能力检查、忙碌态、15 秒超时、权限与系统错误中文提示、服务端保存失败时撤销本地订阅，以及关闭推送的服务端同步检查。
4. 原学习 E2E 通过 API 直接提交复习，没有验证用户页面。现改为页面勾选答案并点击“提交复习”。
5. 三处 `align-items: end` 触发 Edge/Autoprefixer 兼容警告，已改为 `flex-end`。
6. 新增真实页面点击验收，覆盖原测试中只通过 API 验证的偏好、收藏、反馈、纠错、离线、搜索、关键词、下载、关系、趋势、管理和推送控件。

## 浏览器推送边界

本地 `VAPID_PUBLIC_KEY`、`VAPID_PRIVATE_KEY` 和 `VAPID_SUBJECT` 均存在；公钥为 65 字节、私钥为 32 字节，公钥可由私钥正确推导，配置有效。Edge 自动化临时用户目录即使获得页面通知权限，微软推送注册服务仍返回 `Registration failed - permission denied`。页面现在会显示明确中文提示，站内订阅新增/删除 API、数据库写入逻辑和 VAPID 投递策略测试均通过，但这不等同于真实用户 Edge 配置上的外部推送送达证据。正式发布前仍需在普通 Edge 用户配置中手动允许通知并完成一次真实推送送达验收。

## 配置结论

本地已配置数据库、认证、通用/分析 AI、邮件、正式站点 URL、Product Hunt、Embedding、VAPID、微信小程序、内部小程序令牌和 Vercel OIDC。学习 AI 可回退到 Analysis/通用 AI；研究代理未配置专用模型时使用可审计的 `rules-v1`，均不是运行阻断项。退订和小程序令牌密钥目前可回退到 `AUTH_SECRET`，正式生产建议使用独立密钥。

当前 `DATABASE_URL` 是 Supabase 6543 事务池连接，不能安全复制为 `DIRECT_URL`。应从同一 Supabase 项目的连接设置取得 5432 直连串，并同时配置到 Vercel 和 GitHub Actions Secrets。`GITHUB_TOKEN`、`GITHUB_TREND_REPOS`、`TREND_PAPER_TOPICS_JSON`、`TREND_FEEDS_JSON` 属于运营数据源选择；在没有明确仓库、主题和合法授权源前不应虚构配置。

Vercel 环境变量名称只读查询因 CLI 下载持续无响应而终止；GitHub CLI 的既有凭据已失效。因此本轮确认的是仓库、本地隔离环境和浏览器链路，不能把 Vercel/GitHub 控制台中的变量状态标记为已核实。
