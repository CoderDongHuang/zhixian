# 安装知线与多平台下载规划

编写及更新日期：2026-10-21。状态：**阶段一开发与浏览器验收已完成；阶段二已完成 Android APK 构建、签名、安装、启动与覆盖升级基础验收，FCM 推送闭环仍待复测**；GitHub 合并/检查状态见第 9 节。原生公开分发仍未发布。

本方案按阶段实施，**阶段二的构建和基础真机验收已完成，推送注册/送达与公开分发仍未完成**；阶段三至五尚未开始。版本范围与实际发布状态仍以 [版本路线图](roadmap.md) 为准；本文件中的“阶段”是实施顺序，不是新的产品版本号。

## 1. 目标与结论

在网站“设置”旁边增加固定的“安装知线”入口，进入独立的安装与下载页面 `/install`。用户可以按自己的电脑或手机系统，找到对应的安装方式、下载入口和简明说明。

覆盖五类平台：Windows、macOS、Linux、Android、iOS/iPadOS。苹果电脑和苹果手机分别展示，不能合并为一个含糊的“苹果下载”。网页本身继续可用，查看安装页不要求登录。

推荐顺序：**安装页面与网页版安装 → Android 测试包 → iPhone/iPad 测试与上架 → Windows 客户端 → macOS 客户端 → Linux 客户端**。安装页先做完整的结构，安装包按实际发布进度逐个平台接入，不必等五类安装包全部完成才提供入口。

## 2. 当前项目基础

以下为规划时核对的实施前基础；阶段一实际完成内容见第 9 节，不代表真机或线上发行验收。

| 范围 | 已有基础 | 后续需要补齐 |

实施前的安装按钮仅在浏览器提供安装事件时出现，安装后会变成悬浮的“清理缓存”按钮。阶段一已改为固定安装入口，保留 Service Worker 注册，将安装事件状态集中管理供安装页使用；缓存管理已迁入“设置 → 应用设置”。

现有原生 App 主要承担阅读、收藏、离线与学习同步，网页还包含完整研究工作台。页面介绍应按各端实际功能撰写，不承诺所有端功能完全相同。

## 3. 参考与页面结构

参考 [Obsidian 官方下载页](https://obsidian.md/download)（2026-10-20 查看）：突出当前设备下载，另外列出 iOS、Android、Windows、Mac、Linux 的入口，并为同一平台保留不同分发形式。知线采用这种清晰的层级，视觉沿用现有白灰背景、深绿色按钮和品牌图标。

页面从上到下分为四部分：

| 区域 | 展示内容 | 用户操作 |
| --- | --- | --- |
| 首屏推荐 | 标题、简介、当前设备推荐方式、可用状态 | 安装网页版或下载当前系统的已发布客户端 |
| 全平台入口 | “电脑端”Windows/macOS/Linux；“手机与平板”Android/iPhone 与 iPad | 手动选择其他系统、查看对应版本或安装说明 |
| 安装指南 | 所选平台、推荐浏览器、三步说明、常见失败原因 | 切换平台并照步骤操作 |
| 常见问题 | 网页版与客户端区别、账号同步、更新、卸载、找不到安装按钮 | 展开答案或继续使用网页版 |

建议首屏文案：

> 安装知线，让行业动态随手可读
>
> 在电脑、手机和平板上使用知线，按你的设备选择安装方式。
>
> [安装网页版 / 下载已发布的客户端]　[查看所有平台]

首版应在推荐区明确显示“网页版应用”，客户端发布后再增加原生推荐。原生下载不可用时，主操作仍通向可用的网页版安装说明。

导航示意：

```text
知线    发现  趋势  研究  学习  阅读  设置  安装知线    用户菜单
```

电脑端把安装入口紧邻“设置”。手机端继续让两者相邻，但需要重新调整导航：当前 CSS 写死六列，不能直接塞入第七项。首选两行排列，确保入口可见、下拉菜单不越界、点击区域足够大；在 360、390、768、1440 像素宽度验证。

## 4. 各平台入口与下载策略

每张卡片包含系统图标、平台名称、可用方式、主按钮、原生状态和辅助说明。有实际文件后才展示版本号、文件大小、更新时间、支持系统与处理器架构。

| 平台 | 第一阶段可提供的操作 | 原生发布后的入口 | 需要说明的差异 |
| --- | --- | --- | --- |
| Windows | “查看 Windows 安装方法”，支持时显示“安装网页版” | “下载 Windows 版”，注明实际包格式及 x64/ARM64 | 推荐 Edge/Chrome；不把网页版标成 EXE 下载 |
| macOS | “查看 Mac 安装方法” | “下载 Mac 版”，按实际产物提供 Apple 芯片/Intel 或通用包 | Chrome 可安装；Safari 添加到程序坞需支持该功能的 macOS/Safari |
| Linux | “查看 Linux 安装方法” | 优先评估 AppImage，再按需求增加 DEB/RPM；注明 x64/ARM64 | 优先验证 Chrome/Chromium；分发包不能假定兼容所有发行版 |
| Android | “添加到主屏幕”，显示支持的浏览器说明 | “下载 Android APK”；Google Play 上架后另设入口 | APK 为可直接安装包，AAB 供商店分发；两者不能混用 |
| iPhone 与 iPad | “查看添加到主屏幕方法” | “通过 TestFlight 体验”或“前往 App Store” | 不提供伪装成普通下载的 IPA；iOS 与 iPadOS 都要验收 |

手机扫码入口可在原生分发阶段增加，二维码编码正式 HTTPS 安装页或真实商店链接，不使用临时构建后台地址。电脑也应能查看和打开手机平台入口。

用户主动选择的平台优先于自动识别。识别失败时显示“选择你的设备”，仍展示所有卡片，不阻断下载。iPad 桌面模式需要单独判断，避免被当成 Mac；设备识别只在本地用于推荐，不新增设备信息上传。

## 5. 按钮状态与交互

网页版安装与原生发布分别记录状态，避免“原生规划中”造成网页版也无法使用。

| 状态 | 界面表现 | 点击结果 |
| --- | --- | --- |
| 浏览器已提供安装事件 | “安装网页版” | 用户点击后调起系统安装确认 |
| 浏览器未提供安装事件 | “查看安装方法” | 展开该系统的分步说明 |
| 已处于网页版独立窗口 | “正在使用网页版应用”及“继续使用” | 返回首页；不重复提示安装 |
| 用户取消安装 | 提示“已取消，可稍后重试” | 保留指南；等待新的安装事件再提供直接安装 |
| 安装失败或环境不支持 | 提供原因、推荐浏览器和“继续使用网页版” | 用户仍可访问网站 |
| 原生版规划中 | “客户端规划中”状态文字 | 不产生下载请求；网页版指引仍可点击 |
| 测试版已可分发 | “下载 Android 测试版”或“通过 TestFlight 体验” | 仅进入已验证的测试分发地址，并说明测试范围 |
| 正式版已发布 | 对应系统的正式下载按钮 | 打开真实安装包或官方商店 |
| 已发布链接暂不可用 | 提示“下载暂不可用”，保留网页版入口 | 不提供失效或占位链接 |

“稍后上线”不做成可点击却无响应的按钮，不虚构发布日期。没有安装包时不显示假的“下载成功”、商店徽章或文件信息。

只能判断当前是否处于 PWA 独立窗口及浏览器明确提供的安装信息，普通网页无法可靠判断设备是否另装了原生客户端；不要据此显示“已安装原生版”。

## 6. 第一阶段的安装说明

以下为说明结构，实施时按当时系统版本和真实菜单文字复核。

| 系统 | 推荐说明 |
| --- | --- |
| Windows | 用 Edge/Chrome 打开知线 → 点击地址栏安装图标，或浏览器菜单中的应用安装项 → 确认后从系统应用入口打开 |
| macOS | 支持的 Safari 中选择“添加到程序坞”；或用 Chrome 打开知线 → 点击安装入口 → 确认安装 |
| Linux | 用支持的 Chrome/Chromium 打开知线 → 点击安装入口 → 确认并从应用启动器打开 |
| Android | 用 Chrome 等支持的浏览器打开知线 → 选择“安装应用”或“添加到主屏幕” → 确认后从桌面打开 |
| iPhone/iPad | 用 Safari 打开知线 → 点击分享 → 选择“添加到主屏幕”并确认；如出现“作为网页 App 打开”，按所需方式选择 |

微信等内置浏览器中优先提示“在系统浏览器中打开”。说明应区分独立网页版应用与普通网页快捷方式；浏览器不支持时提供继续访问网站的路径。

常见问题至少包括：

- **现在能下载哪些版本？** 根据真实状态展示，首版以网页版安装为主。
- **网页版安装与原生客户端有什么区别？** 网页版通过浏览器安装并独立打开；原生版需对应系统安装包或商店，离线和后台能力按实际支持说明。
- **多个设备的数据会同步吗？** 同一账号已支持的收藏、阅读与学习数据按现有同步规则处理；本地离线缓存和系统权限分别管理。
- **为什么没有安装按钮？** 可能已在独立窗口、浏览器不支持或未满足安装条件；提供手动步骤，不仅显示错误。
- **怎么更新和卸载？** 网页版随站点更新并受缓存影响；原生版区分商店更新、APK 更新与兼容范围内的 OTA。卸载说明按系统分别提供。

## 7. 分阶段实施清单

- [x] 在“设置”旁增加“安装知线”，页面路径为 `/install`，无需登录。
- [x] 完成当前设备推荐、五平台卡片、指南、常见问题及网页版入口。
- [x] 集中管理现有安装事件与安装状态，保留 Service Worker 注册。
- [x] 原生版先展示真实的规划/待发行状态；预留分发数据结构。
- [x] 调整移动导航和卡片布局，保留键盘焦点、选中状态与可访问名称。
- [x] 完成自动检查、桌面/手机视口浏览器点击检查与截图检查。
- [ ] 补齐各系统真实安装、独立启动和卸载验收；不以模拟事件或手机视口替代。

交付物：实际签名 APK、真实设备记录、可用下载链接。验收：普通测试用户可从安装页下载并安装；下载完成不等于安装完成，不将测试包标为正式版。Google Play 与其他应用市场按目标用户需求另行接入。

## 8. 实现与发布数据约定

第一阶段以静态类型化配置管理平台，不引入下载后台或数据库表。建议文件划分，实施时可按项目规范调整：

| 文件/位置 | 责任 |
| --- | --- |
| `app/site-header.tsx` | 固定安装入口、当前页状态 |
| `app/install/page.tsx` | 页面与搜索引擎标题“安装知线 · 多平台下载” |
| `app/install/install-client.tsx` | 本地设备识别、手动选择、安装交互和指南 |
| `app/install/platforms.ts` | 系统名称、说明、分发方式和真实发布状态 |
| `app/pwa-registration.tsx` 或共享 provider/hook | Service Worker 和一次性的安装事件管理 |
| `app/design-system.css` | 安装页样式、导航与响应式适配 |
| `tests/e2e/` | 安装入口、平台切换、安装状态与窄屏行为回归 |

原生下载数据后续增加：平台、渠道、状态、版本、构建号、架构、最低系统、HTTPS 地址、文件大小、SHA-256、发布日期与发行说明。只有状态可分发且目标地址验证通过时才展示下载按钮；地址存在本身不足以证明已发布。

安装包存放在稳定的发行存储或正式商店，不提交到 Git 源码目录，也不把大量二进制文件放入网站静态资源。测试链接到期后及时回退到说明页；撤下故障版本入口时保留发行记录。不得把签名密钥、商店密钥或后台访问令牌传到页面。
